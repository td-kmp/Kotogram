The phone block, made of TextField

Today the block lays out its own rows over a bare BasicTextField, with its own heights, type and a monospaced number. Proposed: one card holding a ListItem for the country and the design system's TextField for the number, in the sizes the other fields already have. Both blocks below are live: type in either, tap the country to try another pattern.

Measures

TextField's: rows of 50 with 16 inside and corners of 10 (40, 10 and 10 on a laptop), so the block is one of the fields and lines up with the password, email and name fields. ListItem's: 52, 20 and corners of 26 (44, 14 and 10), a piece of the country list. The reference is nearer the first: about 12 at the corners and 16 inside, read off the screenshot by eye.

Fill

The fields' fill, as now, or a grouped card. Switch the theme to Light: the fields' #F4F4F4 all but disappears on the sign-in backdrop #EFEFF3. That is true of the current card and of every TextField on these screens, so it is better settled for all fields at once than here. surface is the reverse: clear by day, faint at night.

Calling code

In the text, as now: one state holds code and number, typing a code picks the country and a pasted international number just works. As TextField's prefix the code is dimmer, fixed, and only the list changes it, so there is no empty or unknown-code state.

Digits

The text font with tabular figures and mask slots one figure wide, as the reference, or the monospaced font the block has now. Either way nothing shifts while typing. In Compose: fontFeatureSettings = "tnum" and a figure dash (U+2012) per slot. Measured in Chrome, not in Compose: in the bundled Inter with tnum a figure and U+2012 are equally wide; in Apple's system font U+2012 is as wide as 0, but tnum left 1 narrower there.

Focus ring

TextField's ring on touch screens: 2 in primary, red on an error. The number takes focus when the screen opens, so the ring would be there nearly always; the reference has none. A laptop has no ring either way. Click into the number to see it.

What it is made of

  1. PhoneNumberField: the card. Its width, shape and fill; it clips its two rows.
  2. ListItem: the country. A headline, a trailing chevron and onClick, which opens OptionPicker. The block lays its measures over the item's default style.
  3. ListItem's divider, from the text's edge, in the block's colour.
  4. TextField: the number. One TextFieldState with the digits of code and number, no fill and no ring of its own. The output transformation writes +998 90 123.
  5. The rest of the mask, drawn under the text in the placeholder's colour: TextField's mask slot.
Column(modifier.width(style.width).clip(style.shape).background(style.containerColor)) {

    TextField(
        state = state,
        readOnly = readOnly,
        inputTransformation = DigitsOnly,
        outputTransformation = format,
        mask = { Text(format.mask(state.text, numberPlaceholder)) },
        keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Phone, imeAction = ImeAction.Done),
        onKeyboardAction = { onSubmit() },
        lineLimits = TextFieldLineLimits.SingleLine,
        style = style.numberStyle,
    )
}
  • TextFieldStyle gains containerColor. The fill is Material's default today and not in the style, so a field can't be a transparent row of a card.
  • TextField gains a mask slot. Tried first: PhoneNumberFormat appending the rest of the pattern itself (TextFieldBuffer.addStyle, allowed inside an output transformation in foundation 1.12.1). A tap right of the digits then drew the cursor after the mask, so the mask is drawn under the text as before, through a slot at the text's origin.
  • PhoneNumberField loses its own BasicTextField, its row, its text styles and the monospaced font. Its style keeps the card and what it lays over the two parts.
  • Unchanged: the parameters the phone screen passes, one TextFieldState in the ViewModel, the error under the block, and a laptop's 80-high card.
  • The catalog gets a page for it. There is none today.
